# Data Engineering & Data Science Portfolio

Репозиторий содержит учебные и практические проекты по анализу данных, построению ETL-пайплайнов и машинному обучению. Основной упор сделан на работу с большими данными с использованием **PySpark**, разведочный анализ средствами **Pandas**, исследование внутреннего устройства вычислений в Apache Spark, оркестрацию пайплайнов с помощью **Apache Airflow**, а также практику в классическом ML на табличных данных (**CatBoost**, **scikit-learn**) и участие в соревнованиях **Kaggle**.

## 📂 Структура репозитория и описание файлов

### 🎓 Учебные проекты

*   **`01_eda_pandas_hiv_fires.ipynb`**
    *   **Тема:** Разведочный анализ данных (EDA).
    *   **Описание:** Работа с табличными данными (мониторинг ВИЧ и лесные пожары) с помощью Pandas. Оптимизация типов данных для экономии памяти, поиск аномалий (метод IQR), визуализация распределений и корреляционный анализ.
*   **`02_spark_sql_ecommerce_etl.ipynb`**
    *   **Тема:** ETL и Spark SQL.
    *   **Описание:** Построение аналитических витрин на данных e-commerce. Соединение таблиц, агрегации, работа через DataFrame API и Spark SQL, экспорт результатов в формат Parquet.
*   **`03_spark_performance_benchmarks.ipynb`**
    *   **Тема:** Оптимизация и внутреннее устройство Apache Spark.
    *   **Описание:** Исследование физических планов выполнения запросов. Сравнение `repartition` и `coalesce`, бенчмарк `Sort-Merge Join` против `Broadcast Hash Join`, влияние кэширования и проблема мелких файлов.
*   **`04_spark_ml_regression.ipynb`**
    *   **Тема:** Машинное обучение (Spark MLlib).
    *   **Описание:** Построение регрессионной модели. Сравнение Linear Regression и Random Forest, обработка категориальных признаков (StringIndexer, OneHotEncoder), оценка важности признаков.
*   **`airflow_dags/`** (папка с `first_dag.py` и `second_dag.py`)
    *   **Тема:** Оркестрация ETL-пайплайнов в Apache Airflow.
    *   **Описание:** Два взаимосвязанных DAG-а. Первый забирает данные по API, отправляет их на почту, читает обратно через IMAP, парсит результат и передает его дальше через XCom, после чего запускает второй DAG. Второй DAG принимает параметры от первого и логирует их.
 
### 🏆 Kaggle

*   **`kaggle_titanic_survival_catboost_ml.ipynb`**
    *   **Тема:** Бинарная классификация (Kaggle — Titanic: Machine Learning from Disaster).
    *   **Описание:** Предсказание выживания пассажиров «Титаника» по табличным данным (891 train / 418 test). Включает разведочный анализ: распределение выживаемости по полу (74.2% женщин vs 18.9% мужчин — обоснование наивного бейзлайна «все женщины выжили»), пропуски в `Age` (~20%) и `Cabin` (~77%). Обучение **CatBoostClassifier** на признаках `Pclass`, `Sex`, `SibSp`, `Parch`, `Age`, `Fare` с нативной обработкой пропусков. Оценка качества через **StratifiedKFold (5 фолдов)**: CV accuracy **0.826 ± 0.018**, что на **+3.9 п.п.** выше наивного бейзлайна (accuracy 0.787 на train). Анализ важности признаков (`get_feature_importance`): пол и класс билета — ключевые драйверы выживания, что согласуется с историческим контекстом эвакуации. Финальный сабмит формируется в `submission.csv` в формате, ожидаемом Kaggle (`PassengerId`, `Survived`).
